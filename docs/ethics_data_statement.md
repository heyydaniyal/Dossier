# Ethics and data statement (draft, Phase 0)

**Status:** draft. Whether NOVA IMS requires a formal ethics/data form is pending professor question (e).

1. **Data.** The project uses only the IBM *Transactions for Anti-Money Laundering* dataset (Kaggle), which is fully synthetic, generated by an agent-based simulator. It contains no real persons, accounts or institutions. Customer/KYC attributes are not in the dataset; any such attributes are synthesised by the team, documented with their generation process, and flagged as synthetic in the app.
2. **No personal data.** No real personal data is collected, stored or sent to any third party. The app has no user accounts beyond the team.
3. **Third-party LLM processing.** Development uses the Google Gemini API free tier. Google may use free-tier inputs and outputs to improve its products. Because only synthetic data is sent, this is acceptable for this project; it would not be for real customer data, and this is stated as a limitation of the deployment choice.
4. **Human in the loop / decision support only.** The system produces recommendations and cited case files. Closing an alert requires analyst confirmation. Filing a suspicious activity report, freezing an account and setting detection thresholds are outside the system and human-only.
5. **Ground-truth firewall.** Labels and the laundering-pattern file are read only by the evaluation harness and the offline simulated-dispositions generator; this is enforced by tests, so reported results are not inflated by label leakage.
6. **Limitations to report.**
   - Synthetic data; results are not evidence of real-world performance. HI→LI transfer is *within-generator cross-variant generalisation*, not external validation.
   - Not tested with real AML analysts (no user study).
   - Historical analyst dispositions are simulated with a documented noise model.
   - LLM outputs vary between runs even at temperature 0; variability is measured and reported.
   - Possible bias: an LLM may reproduce stereotypes (e.g. about countries or names) if such fields exist; synthetic KYC fields are designed to avoid protected attributes, and this is checked during evaluation.
7. **Misuse.** The system summarises evidence and recommends; it does not produce instructions for evading detection. Rule thresholds and model internals shown in the app are those of a synthetic benchmark.
